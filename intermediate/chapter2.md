# 第2章 アプリケーションアーキテクチャ

## Q9. レイヤードアーキテクチャ

**問題：** Controller / Service / Repository の役割を説明してください。また、なぜ分離するのか、Controller と Service の責務の境界はどこかも答えてください。

**回答：**

Controller は窓口を担当します。Service は処理を担当します。Repository はデータベースの倉庫番を担当します。

分離する理由は、1つのクラスにまとめると、ルールを変えたいとき（Service の領域）に、窓口（Controller）の部分まで一緒に直すことになって困るからです。

Controller と Service の境界は、チェックまでが Controller、判断からが Service です。

## Q10. DTOパターン

**問題：** エンティティを直接 API に使わない理由を説明してください。

**回答：**

エンティティを直接 API に使わない理由は、3つあります。

1つ目は、パスワードの列を出してはいけないからです。ハッシュ化されていても、同じハッシュ値になるものを探し当てる可能性があります。

2つ目は、列の名前を変えたときに、画面側が項目を探せなくなるからです。見せる用のコピーがあれば、画面側はコピーの形だけを見ていればよく、直さずに済みます。

3つ目は、パスワードを書き換えられて、そのまま乗っ取られるおそれがあるからです。

## Q11. グローバル例外ハンドリング

**問題：** 各 Controller で try-catch する場合と比較した、グローバル例外ハンドリングの利点を説明してください。

**回答：**

グローバル例外ハンドリングの利点は、各 Controller で try-catch する場合と比べて、3つあります。

1つ目は、同じエラー処理が Controller の数だけできてしまうのを、1か所にまとめられることです。

2つ目は、新しい Controller を追加したときに、エラーの処理がなくなるのを防げることです。

3つ目は、エラーの返し方が1つにそろうので、何のエラーかがわかり、画面側がどう対処すればよいか決められることです。
