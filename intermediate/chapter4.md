# 第4章 インフラとデプロイ

## Q22. Docker / docker-compose

**問題：** Dockerの概要と、ローカルインストールとの違いを説明してください。

**回答：**

ローカルインストールとは、自分のPCに直接ソフトを入れることです。Dockerとは、アプリを動かすために必要なものをひとまとめにした箱のようなものです。

ローカルインストールは、人によってPCの環境が違うため、AさんのPCで動いても、BさんのPCでは動かないことがあります。Dockerは、必要なものを箱にまとめるので、どのPCでも同じように動きます。

また、不要になったとき、ローカルインストールはアンインストールが必要ですが、Dockerはコンテナを削除するだけで済みます。

## Q23. AWS基本サービス

**問題：** EC2 / RDS / ALB / S3 の役割と分離理由を説明してください。

**回答：**

EC2 は、AWS での自分のPCの代わりになります。RDS は、AWS で DB の役割を担います。ALB は、受付として、来た通信を EC2 に振り分けます。S3 は、画像などのファイルを置く資材置き場です。

これらを分ける理由は、1つにまとめると、EC2 が入れ替わったときに、DB のデータや画像も一緒に消えてしまうからです。分けておけば、EC2 が入れ替わっても消えません。また、ALB があれば、利用者が増えても対応できます。

## Q24. IaC（Terraform）

**問題：** 手動構築との違いとメリットを説明してください。

**回答：**

手動構築は、そもそも手作業であるため、間違える可能性があり、メモでも残していなければ同じことができないという問題があります。IaC（Terraform）は、構成をコードにするので、全く同じ構築を再現することができます。

メリットは、間違えて作ってしまったときも、コードを修正して作り直すことができる点です。

## Q25. 環境変数と機密情報

**問題：** ソースコードに直接書く問題点と、安全な管理方法を説明してください。

**回答：**

ソースコードに直接書くと、そこに書いたパスワードを悪用できてしまうという問題があります。また、パスワードを変えたいときは、コードを変えなければならなくなります。

安全な管理方法は、環境変数や Secrets Manager のような、コードの中ではなくコードの外に置くことです。そうすると、安全にしまえるので、漏れる危険が減るという利点があります。また、コードを変える必要がなくなります。
